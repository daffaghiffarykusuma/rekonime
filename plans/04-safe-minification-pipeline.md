# Plan 04 - Safe Minification Pipeline

Severity: High  
Priority: P0

## Objective

Replace regex-based minification with parser-safe tooling.

## Risks Addressed

1. Regex stripping can corrupt JS/CSS syntax.
2. Hard-to-debug production breakage risk.

## Implementation Plan

1. Retire `tools/minify-static.js` for JS/CSS minification.
2. Use Vite/Rollup/esbuild minification for JS.
3. Use PostCSS/cssnano (or Vite CSS minifier) for CSS.
4. Keep source maps in non-prod mode for debugging.
5. Add snapshot/size checks to verify minified output remains valid.

## Validation

1. Compare functional parity before/after minifier swap.
2. Run unit + e2e tests against production build.
3. Run smoke test for pages with heavy inline templates.

## Exit Criteria

1. No custom regex minifier in release path.
2. Minified assets generated by syntax-aware tools only.
